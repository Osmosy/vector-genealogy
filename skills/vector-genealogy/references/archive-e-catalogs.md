# Электронные каталоги региональных архивов (ЕАИС, АИС, порталы читальных залов)

Читайте, когда нужно узнать, что за дело хранится в областном архиве и оцифровано ли оно, до
любой переписки с архивом и до регистрации на портале. Правило: **метаданные бесплатны, сканы —
нет**. Состав фондов, описей и дел (заголовки, годы, листаж, отметка «Отсканировано» и число
кадров) региональные порталы отдают анонимному посетителю; клик по делу редиректит на вход
(например `…/userLogin.jsf?faces-redirect=true`). Поэтому порядок такой: снять инвентарь без
входа → записать шифры в дело → и только потом решать, нужен ли личный кабинет.

## Как устроены такие порталы

Типовой региональный портал (проверено на ЕАИС Липецкой области, `arhiv-lo.admlr.lipetsk.ru`) —
JSF/PrimeFaces-приложение: вся навигация и фильтры идут AJAX-postback'ами, отдельных URL у
страниц фонда/описи/дела нет.

- **Не собирать ссылки — кликать.** У «кнопок» `href="#"` и `onclick="PrimeFaces.ab({s:'form:…'})"`.
  Искать элемент по тексту (`ОКУ "ГАЛО"`, `Описи дел, документов`, `Единицы хранения`, `Поиск`)
  и кликать; после каждого клика ждать 8–12 с и заново читать отрисованный текст.
- **Выбор архива — это `<select>`**, а не ссылка в дереве: у ЕАИС ЛО `#form:j_idt118_input`,
  нужное значение — по тексту опции (`ОКУ "ГАЛО"`). Клик по `span.ui-menuitem-text` ничего не делает.
- **Фильтры заполнять нативным сеттером**: `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el, 'Ключи')`
  + события `input` и `change`, затем клик по кнопке с текстом `Поиск`. Присваивание `el.value = …`
  PrimeFaces не видит, и поиск уходит с пустым фильтром.
- **Данные — карточки, не таблицы.** `li.ui-dataview-row` / `div.na-card`, текст вида
  «Ф. 000. Оп. 1. Д. 94. / Метрические книги … / Отсканировано / Листов 519 / Отсканировано 1048».
  Сбор через `table tbody tr` даёт «Данные не найдены» на странице, где данные есть, — это артефакт
  парсера, а не пустая выдача.

## Сквозной поиск по делам и проверка охвата по годам

Верхняя вкладка **«Единицы хранения»** (без выбора фонда) ищет по делам всех архивов сразу — это
самый быстрый способ узнать, что вообще оцифровано по селу и за какие годы.

- Поле `ЗАГОЛОВОК` = основа фамилии/села (`Ключи`, `Иванов`) выдаёт дела из **разных** фондов:
  метрики, акты ЗАГС, колхозные и бюджетные дела. Так по одному селу сразу нашлись книги актов
  гражданского состояния (фонд Р-18) и личные дела 1930-х в другом фонде.
- Поле `ЗАГОЛОВОК` = тип документа (`актовые записи`, `гражданского состояния`) даёт перечень
  ЗАГС-фондов региона с хронологией — с него начинать, если нужны акты после 1918.
- Поле `ГОД` + тип документа — это **доказательство отсутствия**: запрос «гражданского состояния»
  с годом 1930 вернул по всей области одну единицу хранения (другой уезд). Такой результат —
  основание писать в отчёте «за этот год оцифровки нет», а не «не нашлось».
- Шифры находок всё равно проверять по карточке дела: сквозная выдача не показывает опись фонда
  целиком, и «дела нет» по одному запросу не означает, что опись пуста.

## Маршрут до дела

1. `…/portal/fundsCatalog/catalog.jsf` (вкладка «Фонды») → выбрать архив в `<select>`.
2. Поиск по фондам: поле `ЗАГОЛОВОК` + `Поиск`. Для метрик запрос `Метрические` сразу даёт все
   метрические фонды региона с хронологией и числом описей — это быстрее перебора номеров.
3. Открыть фонд → вкладка «Описи дел, документов» → опись → вкладка «Единицы хранения».
4. Внутри описи поле `ЗАГОЛОВОК` = название села (`Ключи`), затем `Поиск` — выдаёт дела именно по
   этому селу с годами и листажом.
5. Записать шифры (фонд/опись/дело, годы, листы, кадры) в `artifact-register.csv`.

Результат такого прохода сразу пригоден для двух вещей: адресного просмотра после входа и
письменного запроса в архив, если вход не нужен или невозможен.

## Ловушки

- **Хардкодить id JSF-полей.** `form:j_idt146` в другой вкладке или после перезагрузки — уже другое
  поле (`form:j_idt433`), и поиск молча уходит с пустым фильтром. Искать по признаку
  (`[...document.querySelectorAll('input[type=text]')].find(i=>i.placeholder==='ЗАГОЛОВОК')`),
  а не по номеру; номера использовать только внутри одного захода.
- **Пустой список единиц при непустой описи.** Счётчик «Количество единиц хранения: 0» на карточке
  описи не означает, что дел нет: у ЕАИС ЛО так помечается опись, дела которой лежат в другой
  описи фонда (по одному селу дела оказались в оп. 1, а не в оп. 3, хотя цитата исследователя ссылалась
  на оп. 3). Проверять все описи фонда, прежде чем писать «не оцифровано».
- **Верить чужой ссылке на шифр.** Номер описи из статьи, форума или дневника может не совпадать
  с каталожным: каталог архива первичен, цитата — нет. Расхождение фиксировать в отчёте.
- **Регистрироваться, чтобы «посмотреть каталог».** Каталог открыт; регистрация нужна только под
  сканы. Не начинать с формы.
- **Форма регистрации как препятствие.** У ЕАИС ЛО она по адресу `…/accOpen/registration.jsf`
  (или кнопка «Создать профиль» на главной) и состоит из шести шагов, но обязателен только первый:
  ФИО, дата рождения, телефон, электронная почта, пароль. «Дополнительные данные», «Образование
  и цель работы», «Данные сопроводителя», «Стать волонтером» пропускаются; в конце — Яндекс
  SmartCaptcha и код подтверждения. Регистрацию на имя пользователя выполняет пользователь;
  агент может заполнить поля, но код и капчу вводит он.

## Что писать в дело

Каталог — это `description`, а не `original`: он доказывает существование и оцифровку дела, но не
содержание записи. В реестре утверждений это `single-source` с пометкой «доступ к образам после
входа», а в «Точке продолжения» — шифр дела, годы и номер первого нужного кадра.
