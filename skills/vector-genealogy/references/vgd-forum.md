# Форум ВГД: выписки из метрик и вложения

Читайте, когда нужный фонд закрыт на сканы, а запись о рождении/браке/смерти всё равно нужна.
Дневники участников ВГД (`forum.vgd.ru`, раздел «Дневники участников») часто содержат
**пофамильные выписки из метрик с номерами записей, датами по ст. ст. и номерами листов** —
это готовый транскрипт, который сильнее любого индекса и дешевле ожидания читального зала.

## Как найти тему

- Поиск: `site:forum.vgd.ru <фамилия> <село>` — темы называются по шаблону
  «<Фамилия> из села <X>» или «<Село> <уезд>»; дневники индексируются внешними поисковиками.
- Внутри темы пагинация адресная: `/<раздел>/<тема>/`, `/<раздел>/<тема>/10.htm`, `/<раздел>/<тема>/20.htm`.
- Модератор раздела обычно исследователь этой же фамилии: у него в теме и цитаты, и файлы,
  и он же отвечает на вопросы о семье. Модератор другой фамилии (смежной) даёт вторую линию.

## Чтение

- Сервис извлечения текста может отдавать `403` на страницы форума при живом браузере —
  читать браузером (`document.body.innerText`), а не HTTP-клиентом.
- Аккаунт на форуме нужен только для публикации; чтение тем и скачивание вложений идёт без входа.
- Публиковать сообщения от чужого/общего аккаунта — только с явного разрешения владельца аккаунта.

## Вложения

Ссылки вида `file.php?fid=<N>&key=<K>` — под одним интерфейсом лежат и документы, и фотографии,
поэтому тип проверять после скачивания, а не по расширению из текста поста:

```bash
curl -sL -A "Mozilla/5.0 … Chrome/157.0" -H "Referer: https://forum.vgd.ru/<раздел>/<тема>/10.htm" \
  "https://forum.vgd.ru/file.php?fid=<N>&key=<K>" -o attach.bin
file attach.bin    # Microsoft Word 2007+ / JPEG / ZIP
```

DOCX разбирается стандартной библиотекой, текст таблиц выписок идёт построчно:

```python
import zipfile, re, html
x = zipfile.ZipFile('attach.docx').read('word/document.xml').decode('utf-8')
x = re.sub(r'</w:p>', '\n', x)
print(html.unescape(re.sub(r'<[^>]+>', '', x)))
```

## Как это идёт в дело

- Выписка участника — `derivative`, а не `original`: в реестре артефактов `source_type=transcription`,
  в утверждении — `single-source`, пока запись не сверена со сканом дела.
- `independence_group` — по архиву и фонду (`g-<архив>-<фонд>`), а не по сайту: цитата с форума
  и скан того же дела не являются двумя независимыми подтверждениями.
- Номер описи в цитате может расходиться с каталогом архива: **каталог первичен**, расхождение
  фиксировать в отчёте (в ЕАИС дело лежало в оп. 1, а цитата ссылалась на оп. 3).
- Из выписок сразу видно следующее поколение: брак называет возраст обоих и поручителей
  (обычно ближайшая родня), рождение — восприемников (часто братья/сёстры матери).
  Это различающий признак для однофамильцев, а не украшение.
- Чужие генеалогические выводы в теме (кто кому отец) не переносятся без записи: брать только
  цитаты с номерами записей и листов.

## Ловушки

- **Считать тему закрытой после первой страницы.** Свежие сообщения и вложения висят на последних
  страницах, а старые цитаты — на первых; читать все.
- **Путать семьи одной фамилии.** В теме «<Фамилия> из села X» пишут потомки разных дворов;
  различать по годам, восприемникам и номерам дворов/хозяйств, а не по фамилии.
- **Ждать от метрик события после 1918 года.** Их там нет: брак 1920-х и рождение 1930-х — это
  ЗАГС, а состав двора 1930–1940-х — похозяйственные книги сельсовета (в теме они тоже
  встречаются как выписки, но по другим фамилиям).
